# Установка и первый вход

[Оглавление](README.md) · [English](../en/installation.md)

## Подготовка

Нужны Linux, достаточно диска и ОЗУ, Docker/Compose и рабочий драйвер GPU.
Для NVIDIA требуется настроенный NVIDIA Container Toolkit; для AMD — доступ
к нужным устройствам GPU. Скачивание контейнера не исправляет драйвер хоста
и не применяет аппаратные анлоки.

Учитывайте размер образа, весов, временное место загрузки/распаковки и результаты.
Размер checkpoint не равен пику VRAM. CPU offload требует свободной ОЗУ и всё
равно использует VRAM для вычислений.

## Установка в картинках — восемь шагов

Все снимки содержат **демонстрационные данные**. Консольные изображения —
иллюстрации с английским переводом подсказок, а не отчёт о реальной установке.
Текст установщика может быть на русском и меняться между версиями. Личный
кабинет снят из настоящего интерфейса с тестовыми ответами API: реальная лицензия
не выпускалась, оплата не проводилась. HWINFO, ключ, пароль и IP на снимках
заведомо нерабочие. **Используйте свои значения, а не данные с картинок.**

### 1. Скачайте, проверьте и запустите установщик в Ubuntu Server

Подключитесь к своему Linux-серверу по SSH или откройте его локальную консоль.
Скачайте публичный [install.sh](../../install.sh):

```bash
curl -fL --proto '=https' --proto-redir '=https' \
  https://raw.githubusercontent.com/rjohny55/ai-server-manager/main/install.sh \
  -o install.sh
bash install.sh --help
bash install.sh auto --download-only
```

Последняя команда скачивает актуальный официальный установщик по HTTPS, но не
выполняет его. Откройте в `less` **именно имя сохранённого файла из вывода**,
изучите его, выйдите клавишей `q` и запустите этот файл через `bash`. Имя файла
на картинке — только пример: на вашем сервере оно будет другим.

Доступны `auto`, `nvidia`, `amd`, `cpu`. Проверьте определённое оборудование и
линию образа. Перед выдачей прав администратора изучите действия скрипта: он
создаёт панель и отдельный обновлятор, может установить Docker. Не запускайте
его поверх рабочей установки без резервной копии и плана переноса.

![Шаг 1: консоль Ubuntu Server — скачивание, проверка и запуск установщика](../assets/install-01-run-en.png)

### 2. Скопируйте код оборудования HWINFO

Следуйте подсказкам. Установщик скачает выбранный образ и получит зашифрованный
**код оборудования HWINFO**. Скопируйте весь код из своей консоли без переносов
строки. Это код для получения лицензии, **не сам лицензионный ключ**. Оставьте
сеанс установщика открытым.

![Шаг 2: пример вывода консоли с кодом оборудования HWINFO](../assets/install-02-hwinfo-en.png)

### 3. Вставьте HWINFO в личном кабинете

Войдите в аккаунт на [сайте проекта](https://ai-server-manager.ru/), откройте
**Личный кабинет → Тарифы**. Выберите тариф и срок, вставьте HWINFO в поле
**Код оборудования** и нажмите **Сгенерировать лицензию**.

![Шаг 3: поле кода оборудования в личном кабинете с тестовым HWINFO](../assets/install-03-account-hwinfo.png)

### 4. Получите и скопируйте лицензию

Выполните условия выбранного тарифа: при необходимости оплату или условия
доступности предложения. До оплаты ключ может быть скрыт частично — такой
замаскированный текст вставлять в установщик нельзя. Когда доступен полный
ключ, скопируйте его либо строку целиком `LICENSE_SIGNATURE=...`. На примере
ниже показано состояние **Ключ получен**. Аккаунт сайта и локальный `admin`
панели — разные учётные записи.

![Шаг 4: личный кабинет — пример полученной лицензии и полного тестового ключа](../assets/install-04-account-license.png)

### 5. Вставьте лицензию в ожидающий установщик

Вернитесь в ту же консоль сервера и вставьте свой ключ по запросу. Принимается
сам ключ или целая строка `LICENSE_SIGNATURE=...`; установщик сохранит его в
защищённом `.env`. Принятие текста установщиком не заменяет проверку лицензии
самим приложением.

Если выбрать `пропустить`, конфигурация может быть подготовлена, но **основная
панель ещё не запускается**. Следуйте напечатанным подсказкам: добавьте лицензию
и запустите панель. До этого форма входа не будет доступна.

![Шаг 5: пример консоли с вводом лицензионного ключа](../assets/install-05-license-en.png)

### 6. Сохраните адрес панели и первоначальный пароль администратора

Дождитесь проверки готовности и сообщения о завершении. При новой установке с
автоматическим созданием пароля вывод содержит администратора `admin`, первый
пароль и адреса панели. Используйте фактический адрес своего сервера и порт из
вывода; для этого установщика обычно это `8088`. Адрес `localhost` подходит,
только если браузер открыт на самом сервере; с другого компьютера нужен адрес
сервера.

Сохраните пароль в безопасном месте. Если вы заранее задали
`ADMIN_INITIAL_PASSWORD`, используйте своё значение. При существующей базе
старый пароль сохраняется: повтор установки или изменение переменной окружения
не сбрасывает пароль пользователя.

![Шаг 6: пример завершения установки — адрес панели и первый пароль admin](../assets/install-06-complete-en.png)

### 7. Войдите в локальную панель

Откройте напечатанный адрес панели в браузере. Введите `admin` и **свой настоящий
первоначальный пароль**, затем нажмите **Sign In**. Это не пароль от сайта.
После входа смените первоначальный пароль. На снимке нет действующих паролей.

![Шаг 7: форма входа на английском с полями логина и пароля](../assets/login-en.png)

### 8. Проверьте главную страницу и видеокарты

Проверьте лицензию, обнаруженные GPU, видеопамять и постоянное хранение. Ниже
показаны тестовые CMP 170HX и модифицированная CMP 50HX 20 ГБ — не замер скорости
и не гарантия такого режима PCIe на вашем оборудовании. Начните с небольшой
совместимой модели и одного запроса, затем переходите к крупным моделям.

![Шаг 8: главная панель в синей теме с демонстрационными GPU и метриками](../assets/dashboard-blue-en.png)

## Совместимость

| Оборудование | На что обратить внимание |
| --- | --- |
| Turing / CMP50HX | Совместимый образ и FP16-пресеты; модифицированные CMP50HX на 20 ГБ отличаются от штатных карт |
| Ampere / CMP170HX и новые поддерживаемые GPU | Подходящие NVIDIA runtime и рецепт модели |
| AMD, включая MI50/gfx906 | AMD-образ; разные семейства ROCm не взаимозаменяемы |
| CPU | Модель и движок должны поддерживать процессорный запуск |

Проверьте, что нужный тег и архитектура действительно опубликованы. Новым
функциям может требоваться более свежая сборка, даже с тем же номером версии.
Тег `-updater` нельзя использовать вместо образа основной панели.

## После установки

До настройки HTTPS, авторизации и прав ограничьте доступ локальной сетью.
Compose, окружение, данные, модели и состояние обновлятора храните вне контейнера
и резервируйте. Не загружайте в GitHub HWINFO, ключи, пароли, cookies и
неочищенные журналы установки.
